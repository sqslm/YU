# 语 YU · V2 右 Alt 统一入口 150 题测试文档

> V2.0 · 2026-10-26 · Windows 端 · 使用 `YU_V2_150_cases.json` 作为机器可读权威用例数据。

## 范围与测试纪律

- **共 150 题：保留 V1 的 YU-001～YU-100，并新增 YU-101～YU-150。** V1 保留项基于上一版测试包，并非已执行或已通过。
- 每题包含“提问/指令、期望动作、前置条件、验收标准”，并给出测试证据与清理要求。
- **严格排除长期记忆系统及相关开发**；任务级短期会话指代不属于长期记忆。
- 测试状态：`PASS / FAIL / NOT_IMPLEMENTED / ENV_BLOCKED / MANUAL_REQUIRED / NOT_RUN`。默认全部 `NOT_RUN`。
- **PASS 必须有真实证据**：路由决策、工具真实返回、数据库记录、实际 Windows 状态、UI 检查或远端回执。模拟只证明隔离逻辑，不可冒充真实桌面 E2E 已通过。
- 无目标仓库、无 Windows GUI、无双屏、未配置模型/邮件/同步等情况按定义标记，**不可虚报 PASS**。
- 危险操作仅测试“权限/确认/取消”或隔离沙箱文件，不碰真实下载目录、私人笔记、真实外发邮件和远端资料。
- 不根据固定测试语句添加硬编码特殊分支；对关键路由用例生成语义改写的变体进行回归。
- **默认只测试，不主动大范围修改业务代码。** 测试结束输出状态、证据、根因线索和最小修复建议；用户另行批准后才按修复任务修改代码。

## 执行优先级

1. 检查当前仓库、现有 `runTool`、`Task Context`、`askAgent`、`AssistantSession`、测试钩子与实际工具注册，确定可测试范围。
2. 先自动执行纯解析/路由/日期计算/参数校验与隔离数据库用例。
3. 再在 Windows 测试环境执行文件、剪贴板、窗口、截图和音频端到端测试。
4. 最后验证外部服务和可选能力；无法满足前置条件时诚实标记原因。
5. 填入 `YU_V2_results.template.json` 的真实结果，利用 `tools/report_results.py` 自动汇总。
