# 给 Codex：执行语 YU V2 150 题自动化自测

请把本任务视为**测试和缺陷诊断任务，默认不要直接重构或大规模修复业务代码**。

1. 先阅读 `tests/yu-v2/README.md`、`YU_V2_150_cases.json` 与 `YU_V2_150_test_plan.md`，然后检查当前 Windows/Electron 仓库的真实实现：右 Alt Pipeline、ASR、路由、Task Context、askAgent、AssistantSession、runTool、提醒/待办/随记、窗口和文件适配器、截图 OCR、工作流、同步及测试钩子。不要假设清单中的功能均已实现。
2. 先运行 `python tests/yu-v2/tools/validate_suite.py` 检查测试集。根据真实仓库建立或复用轻量的测试驱动/夹具。尽可能直接复用现有工具 API、路由入口和数据库隔离配置；不要开发新的重型测试框架。
3. **按编号执行全部 150 题，自动化优先**：纯路由/解析/权限和工具 Schema 做单元或集成测试；数据库操作用隔离 DB 和可控时钟；Windows 工具在真实 GUI 会话用临时目录/真实状态验证；截图/多屏/TTS 需要人工确认的明确记录；外部 API、邮件、推送、云同步需要现有合法配置与预算授权，缺失则记录 `ENV_BLOCKED`，不得擅自发送。
4. 真实语音/GUI 不可自动执行时，不要把文本模拟视为完整 E2E PASS。分别标明已验证层次，并将待人工步骤和判断标准写明。仅模型返回“已完成”不算成功；必须验证工具调用、数据库、文件、窗口、通知、远端回执或明确错误等证据。
5. 使用 `YU_V2_results.template.json` 为模板另存为 `YU_V2_results.json`，确保每条记录包含真实状态、实际表现、可核查证据、疑似根因（注明未证实）、需要的人工复测步骤和耗时。六种状态：`PASS/FAIL/NOT_IMPLEMENTED/ENV_BLOCKED/MANUAL_REQUIRED/NOT_RUN`。未实际运行的一律 `NOT_RUN`。
6. **严格禁止**：新增或测试长期记忆；硬编码测试语句或预期答案到产品；模拟执行成功；未经确认删除/覆盖真实用户文件；未经授权上传私人截图和笔记；在产品运行中随意更改用户账户、全局音量、同步服务器或真实提醒。所有测试尽量在沙箱中执行并恢复环境。
7. 最后运行 `python tests/yu-v2/tools/report_results.py tests/yu-v2/YU_V2_results.json`，生成分模块报告，按 P0/P1 与共同根因聚合失败，列出“已复现缺陷 / 尚未实现能力 / 环境受限 / 待人工验收 / 未执行”，提出 KISS/YAGNI 最小修复方案；**先输出报告和修复建议，不擅自开展大规模修复**。
8. 最终回复：运行环境与版本、各状态数量、各模块成功率（仅已验证项作分母并同时显示覆盖率）、重要失败证据、可能的共性根因、未测原因、复测清单与生成文件位置。提供 `YU_V2_results.json` 和 Markdown 报告。不要编造运行结果或性能提升数据。

如果压缩包不是解压在 `tests/yu-v2/`，先自动定位实际测试文件目录后调整命令，不要因此放弃执行。
